# Research (planning, verified 2026-09-22): Windows 11 Home operations: auto-start of the web and worker processes (PM2 vs NSSM), start.bat/stop design, LAN firewall, keeping the PC awake and Windows Update restarts, native Node modules without build tools, Node 24 LTS status

Collected before the plan was written. Re-verify anything marked UNVERIFIED before relying on it.

## Summary

Use NSSM to run the app at startup, not PM2. PM2 7.0.4 has no Windows startup support: its own docs send you to pm2-installer, whose last commit was in December 2022 and which has open "service won't start / newer PM2 not supported" issues. pm2-windows-startup only adds a registry Run entry, so it starts after the user logs in, not at boot. NSSM has not had a new build since 2.24-101 (2017), but it is a small, stable Windows service wrapper. It is the build winget installs (NSSM.NSSM). It gives us everything we need: restart on crash (on by default), delayed auto-start, run as a chosen account (it grants "Log on as a service" itself), log capture with online rotation, a graceful Ctrl+C stop and killing the whole process tree. The design is two NSSM services, OutreachWeb (node.exe running next start) and OutreachWorker (node.exe running the compiled worker). Both run with the project folder as their working directory, under the owner's account (.\polyg). This account is a Microsoft account with Windows Hello-only sign-in turned on, so the service needs the real Microsoft account password (not the PIN). The fallback is the password-free virtual account NT SERVICE\<name> plus an icacls grant on the project folder. Checks on the owner's PC (read-only) found four risks. It is a laptop. The Wi-Fi network 'HOME-Ground  2' is set to Public. Two existing 'Node.js JavaScript Runtime' firewall rules allow node.exe on the Public profile. Hibernate-after is 3 hours on AC. So setup must: switch the network to Private, add a firewall rule for TCP 3000 limited to Private and LocalSubnet, disable the Public node rules, and set standby and hibernate timeouts on AC to 0 and the lid action to 'Do nothing'. Windows 11 now groups update restarts into one per month (updates from 2026-07-28 on), scheduled outside active hours (maximum 18 hours). Setting active hours to about 08:00-02:00 PKT keeps restarts away from EU sending hours (roughly 11:00-23:00 PKT). NSSM services come back after a reboot without anyone logging in. No native module needs Visual Studio Build Tools. better-sqlite3 13.0.3 moved to Node-API and ships prebuilds/win32-x64.node with no install script. But @prisma/adapter-better-sqlite3 7.10.0 still depends on better-sqlite3 ^12.6.0, which downloads better-sqlite3-v12.11.1-node-v137-win32-x64.tar.gz from GitHub through an install script (the file exists). npm 12 (now the npm 'latest' tag, 12.0.2) turns dependency install scripts off by default, so package.json needs an allowScripts entry. Use @node-rs/argon2 2.2.1 for password hashing: napi-rs prebuilt for win32-x64-msvc, no install scripts, Argon2id by default, and on Next.js's built-in serverExternalPackages list. Node 24 (Krypton) is the right LTS today: Active LTS until 2026-10-20, then Maintenance, end of life 2028-04-30. The owner should update from 24.18.0 to 24.21.0 (24.18.1 was a security release). Node 26 becomes LTS on 2026-10-28 and is a later upgrade option, not a need now.

## Gotchas

- PM2 on Windows: `pm2 startup` does not support Windows. pm2-installer is unmaintained since 2022-12, runs as Local Service with PM2_HOME=C:\ProgramData\pm2 and has open 'service won't start' issues. pm2-windows-startup only uses a registry Run key, so nothing runs until someone logs in, and it stops at logoff.
- NSSM: use build 2.24-101, not 2.24 (Creators Update+ start bug). nssm.cc and git.nssm.cc were down or timing out during research, and winget also downloads from nssm.cc/ci. Keep a checked copy of nssm.exe (SHA256 of the zip: 99F5045F...D07B8) in the project's tools folder and register services from there.
- NSSM log rotation renames old files (e.g. web-20260922T101500.123.log) but never deletes them. Plan a cleanup job for logs older than about 14 days, or the disk slowly fills.
- NSSM stop gives the app 1500 ms per stop method by default. At Windows shutdown, services only get WaitToKillServiceTimeout = 5000 ms (value on this PC). So the worker must be crash-safe (idempotent sends, lease-based locks) and cannot count on a graceful stop.
- The owner signs in with a Microsoft account (PrincipalSource=MicrosoftAccount) with Windows Hello-only sign-in ON. A service running as .\polyg needs the Microsoft account password (not the PIN). If that password changes later, both services fail at the next start with error 1069 until it is re-entered. We could not confirm (verified=false) whether passwordless mode blocks service password logon when the account has never signed in with a password on this PC. Test it during setup, and use NT SERVICE\<name> virtual accounts if it fails.
- Starting, stopping or restarting services needs admin rights (default service DACL). stop.bat/update.bat/install-services.bat must self-elevate (UAC prompt). `nssm status` / `sc query` work without elevation.
- Running `next build` while `next start` (the OutreachWeb service) is running overwrites .next under the live server. update.bat must stop OutreachWeb (and the worker, if its code changed), build, then start again.
- In .bat files, `npm` is npm.cmd, which is itself a batch file. Without `call npm ...` the calling .bat silently ends when npm finishes. Better to call `node node_modules\next\dist\bin\next ...` directly. In PowerShell, `npm` resolves to npm.ps1, which is blocked when the execution policy is Restricted (the default on fresh Windows when nothing is set).
- .bat files saved with LF-only line endings can break labels/goto/call :label. Keep .bat files CRLF, e.g. with a .gitattributes/.editorconfig rule (verified=false).
- Node on Windows: child.kill() is always a hard kill (like SIGKILL). Closing the console window sends SIGHUP and Windows kills Node about 10 s later. SIGTERM is never delivered. Graceful child shutdown in start.bat mode must go over IPC (fork/ipc channel, a 'shutdown' message). The NSSM stop (Ctrl+C) reaches Node as SIGINT.
- Firewall: the owner's Wi-Fi 'HOME-Ground  2' is currently Public, so a Private-only rule does nothing until the network is switched to Private. Two existing 'Node.js JavaScript Runtime' Allow rules for the Public profile already expose any node.exe port on public Wi-Fi. Also, if anyone ever clicked Cancel on a node.exe firewall prompt, the Block rules it created override our Allow rule (block beats allow).
- The PC is a laptop (PCSystemType=2) with S3 sleep only (no Modern Standby), so sleep means fully offline. The lid-close default is Sleep. Hibernate-after is currently 3 h on AC, which would stop the worker mid-afternoon even though Sleep-after is already Never.
- Don't run `powercfg /hibernate off` on this laptop. It also disables Fast Startup and removes hibernate-on-critical-battery, which protects the machine during load-shedding. Set hibernate-timeout-ac 0 instead.
- Allow wake timers is 'Important wake timers only' on AC. A Task Scheduler task with WakeToRun will not wake the PC unless RTCWAKE is set to 1 (Enable). With S3 sleep the network is off while asleep, so keeping the PC awake is simpler than waking it on a timer.
- Active hours are capped at 18 hours. Since the 2026-07-28 updates, Windows 11 restarts once a month (after Patch Tuesday) outside active hours. Emergency or out-of-band updates can still install outside that pattern. Whether the Settings UI allows active hours that cross midnight (e.g. 08:00-02:00) was not verified.
- After Node 26 becomes LTS on 2026-10-28, `winget upgrade OpenJS.NodeJS.LTS` will probably move the PC to Node 26 (verified=false). Upgrade Node on purpose from the nodejs.org MSI, or pin a version with winget --version.
- npm 12 (now npm's 'latest' tag) blocks dependency install scripts by default. better-sqlite3 12.x (pulled in by the Prisma adapter) then has no .node binary and fails at runtime with a 'could not locate the bindings file'-style error. prisma (preinstall) and @prisma/engines (postinstall) also have scripts. The effect of skipping @prisma/engines postinstall on `prisma migrate` was not verified.
- better-sqlite3 12.x downloads its prebuilt binary from github.com during install. If that download fails (proxy, outage), it falls back to `node-gyp rebuild`, which fails without VS Build Tools + Python. better-sqlite3 13.x ships its binaries inside the npm tarball and avoids this.
- argon2 0.45.1's Windows prebuild is named prebuilds/win32-x64/argon2.glibc.node; the name is cosmetic and it is the Windows binary. The package also lists cross-env as a runtime dependency.
- Next.js PORT cannot come from .env. Pass `-p 3000` on the command line (or PORT in the NSSM AppEnvironmentExtra).
- Some third-party antivirus products (ESET, Malwarebytes reports) have flagged nssm.exe because malware also bundles it. Windows Defender generally does not (verified=false). Smart App Control is Off on this PC; if it were On, it could block unsigned nssm.exe.

## Plan implications

- Auto-start: use NSSM (not PM2) with two services, OutreachWeb and OutreachWorker, set to SERVICE_DELAYED_AUTO_START. They run independently, so the web app can restart without interrupting sending. Explain it to the owner as: 'Windows itself keeps two programs running in the background, starts them when the PC boots (even before you log in), and restarts them if they crash.'
- Services run node.exe directly, not npm, npx or a .cmd shim, so Ctrl+C and the process-tree kill reach the real process. OutreachWeb: Application = full path from (Get-Command node).Source (C:\Program Files\nodejs\node.exe); AppParameters = `node_modules\next\dist\bin\next start -p 3000 -H 0.0.0.0`; AppDirectory = project folder. OutreachWorker: AppParameters = the compiled worker entry (e.g. `dist\worker.mjs`, bundled with esbuild/tsup; tsx is not recommended for the service).
- Exact install script (scripts\install-services.ps1, run elevated via install-services.bat using `powershell -NoProfile -ExecutionPolicy Bypass -File`), for each service: `nssm install OutreachWeb "C:\Program Files\nodejs\node.exe"`; `nssm set OutreachWeb AppParameters "node_modules\next\dist\bin\next start -p 3000 -H 0.0.0.0"`; `nssm set OutreachWeb AppDirectory <project>`; `nssm set OutreachWeb Start SERVICE_DELAYED_AUTO_START`; `nssm set OutreachWeb ObjectName .\polyg <password>` (read with Get-Credential, never echoed or written to disk); `nssm set OutreachWeb AppEnvironmentExtra NODE_ENV=production NEXT_TELEMETRY_DISABLED=1`; `nssm set OutreachWeb AppStdout <project>\logs\web.log`; `nssm set OutreachWeb AppStderr <project>\logs\web.log`; `nssm set OutreachWeb AppRotateFiles 1`; `nssm set OutreachWeb AppRotateOnline 1`; `nssm set OutreachWeb AppRotateSeconds 86400`; `nssm set OutreachWeb AppRotateBytes 10485760`; `nssm set OutreachWeb AppExit Default Restart`; `nssm set OutreachWeb AppRestartDelay 5000`; `nssm set OutreachWeb AppStopMethodConsole 4000`; `nssm start OutreachWeb`. Repeat for OutreachWorker with logs\worker.log. Provide uninstall-services.bat (`nssm stop` then `nssm remove <svc> confirm`) and status.bat (`nssm status`, no elevation).
- Service account: default to the owner's account (.\polyg), as the brief asks, so the services have the same file access as the owner. The install script checks that the service really started (nssm status is SERVICE_RUNNING and the /api/health endpoint responds). If logon fails (error 1069, e.g. Microsoft-account/PIN-only issues), it offers the password-free fallback: ObjectName 'NT SERVICE\OutreachWeb' / 'NT SERVICE\OutreachWorker' plus `icacls <project> /grant "NT SERVICE\OutreachWeb:(OI)(CI)M" "NT SERVICE\OutreachWorker:(OI)(CI)M"`. Never use LocalSystem.
- start.bat (double-click, manual/production mode): cd /d "%~dp0"; check `where node` and major version 24 or 26; if OutreachWeb or OutreachWorker is RUNNING (sc query), print 'already running as a Windows service at http://<ip>:3000' and exit so there is never a second worker; if node_modules is missing, `call npm ci`; then `node scripts\run-prod.mjs`. run-prod.mjs does: prisma migrate deploy; `next build` only if .next\BUILD_ID is missing or a stored source-hash marker changed; forks web and worker with IPC; writes run\supervisor.pid; prefixes their output and writes daily log files; restarts the worker with backoff if it crashes; on SIGINT/SIGBREAK/SIGHUP or a stop request, sends {type:'shutdown'} over IPC, waits up to 8 s, then runs `taskkill /PID <pid> /T /F`.
- stop.bat: if the services are installed, self-elevate (`net session >nul 2>&1 || powershell -NoProfile -Command "Start-Process -FilePath '%~f0' -Verb RunAs"`), then `nssm stop OutreachWorker` followed by `nssm stop OutreachWeb` (worker first so in-flight sends finish). Otherwise run `node scripts\stop.mjs`, which writes run\stop.request for the supervisor and falls back to `taskkill /PID <supervisor pid> /T /F` after a timeout. update.bat: stop services, `call npm ci`, migrate, `next build`, start services.
- Worker robustness this implies: a DB-backed singleton lease/heartbeat row so two workers can never send at once; handlers for SIGINT, SIGBREAK, SIGHUP and IPC 'shutdown' that stop claiming jobs and finish within about 4 s; every send idempotent and reconciled on startup (catch-up), because Windows shutdown gives services only 5 s and power cuts happen. The dashboard should show the worker's last heartbeat and flag gaps (the PC slept or was off).
- Logs: services write logs\web.log and logs\worker.log (NSSM online rotation at 10 MB or daily). Manual mode writes logs\web-YYYY-MM-DD.log. The worker's daily maintenance job deletes logs\*.log older than 14 days, because NSSM never deletes rotated files.
- Firewall (one elevated setup-network.ps1): `Get-NetConnectionProfile`; `Set-NetConnectionProfile -InterfaceAlias "Wi-Fi" -NetworkCategory Private` (or Settings > Network & internet > Wi-Fi > <network> > Network profile type > Private); `New-NetFirewallRule -Name "Outreach-Web-In" -DisplayName "Outreach web app (TCP 3000, private network only)" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 3000 -Profile Private -RemoteAddress LocalSubnet`; disable the existing Public node allow rules with `Get-NetFirewallRule -DisplayName "Node.js JavaScript Runtime" | Disable-NetFirewallRule`; and remove any Block rules for node.exe. Cloudflare Tunnel is outbound-only and needs no inbound rule. The app port is fixed at 3000.
- Keep-awake (README section plus an optional elevated keep-awake.bat): `powercfg /change standby-timeout-ac 0`; `powercfg /change hibernate-timeout-ac 0`; `powercfg /setacvalueindex SCHEME_CURRENT SUB_BUTTONS LIDACTION 0`; `powercfg /setactive SCHEME_CURRENT`. Leave the DC/battery settings and hibernate-on-critical-battery alone. Tell the owner: keep the laptop plugged in, and closing the lid is fine once this is set. Check with `powercfg /q SCHEME_CURRENT SUB_SLEEP` and `powercfg /requests`. No wake timers are needed.
- Windows Update: README tells the owner to set Active hours manually to 08:00-02:00 (18 h max) in Settings > Windows Update > Advanced options, which covers EU working hours (about 11:00-23:00 PKT across EET/CET/GMT). The monthly restart then falls between 02:00 and 08:00 PKT. NSSM services restart automatically after it without a login. Optionally pause updates (max 35 days) during a big campaign.
- Native modules: the plan needs no Visual Studio Build Tools. Use @node-rs/argon2 2.2.1 (Argon2id defaults) for password hashing. Don't list better-sqlite3 directly; let @prisma/adapter-better-sqlite3 bring 12.x. Do backups with SQLite `VACUUM INTO` through Prisma rather than a second better-sqlite3 copy. Commit a package.json allowScripts policy, generated after the first install with `npm approve-scripts --allow-scripts-pending` and then approving prisma, @prisma/engines and better-sqlite3 pinned to exact versions, so installs keep working if npm 12 arrives.
- Node: set package.json "engines": {"node": ">=24.18.1"}, and have start.bat warn if `node -v` is not 24.x or 26.x. README step 1: install or upgrade to Node 24.21.0 from the nodejs.org Windows x64 MSI (default path C:\Program Files\nodejs, which the services reference). Re-run install-services only if the Node path changes.
- Scripts: all owner-facing entry points are .bat files (CRLF line endings) that call Node scripts or `powershell -NoProfile -ExecutionPolicy Bypass -File ...`. Nothing relies on bash, and nothing relies on the machine's PowerShell execution policy.
