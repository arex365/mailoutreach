# Research (planning, verified 2026-09-22): Supporting libraries: spreadsheet/CSV import and export, countries and time zones, date math, running the TypeScript worker, table UI, validation, email hygiene, tests, login rate limiting, secret encryption, live updates (SSE or polling)

Collected before the plan was written. Re-verify anything marked UNVERIFIED before relying on it.

## Summary

I checked these on 2026-09-22 against npm, the official docs and local Node 24.18 runs. Spreadsheet import: use SheetJS CE 0.20.3 (Apache-2.0) installed from the SheetJS CDN tarball, and keep a copy in the project. It is the only candidate that reads both .xlsx and legacy .xls. The npm-registry `xlsx` 0.18.5 is from 2022 and still has both CVEs. exceljs 4.4.0 (last release Oct 2023) only handles XLSX/CSV, and read-excel-file 9.3.10 only handles .xlsx. CSV and pasted rows: use papaparse 5.7.0 for both parsing and writing. It auto-detects the delimiter (comma, tab, semicolon and more), strips a BOM, supports 'greedy' empty-line skipping, and `unparse` has an `escapeFormulae` option; we add the UTF-8 BOM to exports ourselves. Countries: use i18n-iso-countries 7.14.0, whose Node entry loads every locale including de/nb/nn/no, plus a small alias map. Do not use countries-and-timezones 3.10.0: it marks Europe/Oslo as a deprecated alias of Europe/Berlin, so Norway comes back as 'Europe/Berlin'. Build country→default zone from Node's built-in Intl, which knows Europe/Oslo, plus a hand-kept 'main zone' table for countries with several zones. Temporal is NOT turned on in Node 24.18 (it only works behind a flag). It is on by default in Node 26, which becomes LTS in October 2026. So the recommendation is temporal-polyfill 1.0.5, kept inside one time-helper module, for DST-safe sending-window math, with Luxon 3.7.2 as the conservative fallback. Worker: use tsx for development and an esbuild bundle (`--packages=external`) run with plain `node` in production. Node's built-in type stripping can't handle enums, parameter properties or tsconfig path aliases, requires `.ts` extensions in imports, and does not strip files under node_modules, so it doesn't fit code shared with Next.js. Pin TypeScript 6.0.3, not 7.0.2: TS 7 ships no JS API and typescript-eslint 8.70.1 (used by eslint-config-next) requires typescript <6.1.0. TanStack Table v9 (9.2.4) has been stable since Aug 2026 and supports React 18+. It renames useReactTable to useTable and requires the features you use to be registered with tableFeatures(); the shadcn data-table guide already uses v9. For 10k+ companies use server-side pagination, not virtualization. Zod 4.6 changed its API (z.email(), `error` param, z.flattenError). Note that the Next.js forms guide still shows Zod 3 code, and server actions have a 1 MB body limit, so file imports should go through a route handler. For notifications and progress, poll instead of using SSE. Cloudflare Tunnel buffers everything except text/event-stream, the proxy read timeout is 125 s, and browsers allow only 6 SSE connections per browser per domain over the office HTTP/1.1 address. The office http://<pc-ip> address is not a secure context, so Secure cookies, navigator.clipboard and desktop notifications all fail there. Login rate limiting and AES-256-GCM secret encryption need no extra libraries: a small database table and node:crypto are enough (I tested the crypto calls on Node 24).

## Gotchas

- TypeScript 7.0.2 is now npm 'latest', so a plain `npm i -D typescript` installs it. TS 7 has no JS API, and typescript-eslint (inside eslint-config-next) requires typescript <6.1.0, so linting would break. Pin typescript@~6.0.3.
- SheetJS: `npm i xlsx` silently installs the 2022 build that has both CVEs. Always install from the CDN tarball or the vendored copy. For legacy .xls with non-UTF-8 text, the ESM build needs `XLSX.set_cptable(cpexcel)` from 'xlsx/dist/cpexcel.full.mjs'.
- SheetJS sheet_to_json with raw:false returns strings formatted like Excel shows them, so dates become ambiguous (e.g. '3/14/24'). Use cellDates:true + raw:true and convert Date objects to ISO. Convert numbers to strings carefully so phone numbers and IDs don't turn into 1.23E+11.
- CSV files that German or Norwegian Excel saves as 'CSV' (not 'CSV UTF-8') are Windows-1252 and use ';'. Decode with TextDecoder('utf-8', {fatal:true}), fall back to 'windows-1252', and let papaparse detect the ';'.
- Excel on German/Norwegian machines expects ';' when a .csv is opened by double-click, so a comma CSV lands in one column. The 'sep=,' first-line trick is said to stop Excel honouring the UTF-8 BOM (not checked in official docs). Offer a semicolon option or an .xlsx export, which SheetJS can write.
- If escapeFormulae adds a leading ' to exported values, the re-import must strip a leading ' before =, +, - or @, or the missing-emails round trip will corrupt values.
- countries-and-timezones 3.10.0 follows the tzdb 'backzone' merge: Norway (and DK and SE) default to 'Europe/Berlin' because Europe/Oslo is marked deprecated. Same UTC offsets, but confusing in the UI. Node's Intl gives Europe/Oslo.
- Node 24's Intl returns legacy CLDR IDs: Intl.supportedValuesOf('timeZone') lacks 'Asia/Kolkata' and 'Europe/Kyiv' (it has Asia/Calcutta and Europe/Kiev), and resolvedOptions() canonicalises to the legacy name. Validate a zone with try { new Intl.DateTimeFormat('en', { timeZone }) } rather than list membership, and keep a curated zone list for the picker.
- Germany has two zones in the data (Europe/Berlin, Europe/Busingen), Spain has Europe/Madrid, Africa/Ceuta and Atlantic/Canary, and so on. Never take 'the first zone'; use an explicit main-zone map.
- Temporal is not available in Node 24.18 without --harmony-temporal. Don't ship experimental flags. Node 26 turns it on and becomes LTS in October 2026. Node 26 also removed --experimental-transform-types.
- Node's built-in type stripping won't run code shared with Next.js unless every import uses a .ts extension and `import type`, there are no enums or parameter properties, and path aliases become '#' subpath imports. TS files under node_modules are never stripped. Bundle or use tsx instead.
- Bundling the Prisma 7 'prisma-client' generator output with esbuild had known issues (prisma#27324). Keep all npm packages external (--packages=external) so only the generated client and our code are bundled. Prove this with a spike in milestone 1, and fall back to `node --import tsx` if it fails.
- tsup is unmaintained (its README points to tsdown). tsdown is still 0.x.
- TanStack Table v9 breaks v8 code: useReactTable is now useTable, features must be registered via tableFeatures(), and row, cell and column methods must not be destructured (they are on prototypes now). Old blog posts and generated code often show v8.
- getSelectedRowModel only returns rows on the current page. For bulk actions across pages, keep your own set of selected IDs and send it to the server.
- lucide-react 1.x removed all brand icons, including Instagram.
- Zod 4: the Next.js docs' own example uses Zod 3 APIs (invalid_type_error, .flatten()). Use the `error` param and z.flattenError(). Object.fromEntries(formData) also contains '$ACTION_' keys, so use z.object (which strips unknown keys by default) rather than z.strictObject.
- Zod's default email regex is ASCII-only (Gmail-like), so IDN domains such as æøå.no fail. Convert the domain with url.domainToASCII() before validating and storing.
- validator.normalizeEmail's defaults remove Gmail dots and +tags and lowercase everything, which changes the address we send to. Never use it for stored addresses. At most use a separate dedupe key.
- Server Actions cap request bodies at 1MB by default, too small for spreadsheet uploads. Upload through a route handler. If proxy.ts runs on that route, bodies over 10MB are silently truncated (no error), and the same applies to Mailgun inbound webhooks, whose signature check would then fail. Exclude upload and webhook routes from the proxy matcher, or cap uploads below the limit.
- Office access over http://<pc-ip>:<port> is not a secure context. Secure cookies are rejected there, so login breaks if Secure is always set. navigator.clipboard.writeText is unavailable, which breaks the 'copy instruction for Claude' button. Desktop Notifications and crypto.randomUUID are unavailable too. Set Secure only when the request arrived over https (x-forwarded-proto from cloudflared), and add a copy fallback (select a textarea + document.execCommand('copy'), or a 'select all' box).
- SSE through Cloudflare Tunnel streams only with Content-Type: text/event-stream (everything else is buffered). There is a 125 s proxy read timeout, so heartbeats are needed. When a Cloudflare Access session expires, EventSource fails without any visible error. Over the LAN (HTTP/1.1) browsers allow only 6 SSE connections per browser + domain, so several open tabs can stall the app. Next's default gzip may also delay chunks.
- The Next server and the worker are separate processes, so an SSE handler would have to poll SQLite anyway to see new notifications. SSE adds no freshness over client polling.
- RateLimiterPrisma is only 'tested with Prisma ^5.8.0'. RateLimiterMemory resets on restart. Behind cloudflared every remote request comes from 127.0.0.1, so the real client IP is only in CF-Connecting-IP, and a LAN client could forge that header.
- GCM: never reuse an IV with the same key (use 12 random bytes per encryption). Always pass authTagLength:16 to createDecipheriv (DEP0182). If the .env key is lost, every saved API key is unrecoverable, and database backups are useless for secrets without that key.
- Vitest 5 changed clearMocks to default true, and vite must be installed as a peer. Vitest can't render async Server Components, so cover those with E2E tests.
- Playwright 1.63 officially lists Windows 11+ (not Windows 10) for running tests. That's fine on the owner's PC but worth knowing, because the spec mentions Windows 10/11.
- papaparse's own ESM/CJS package has no bundled types (@types/papaparse is at 5.5.2 while papaparse is at 5.7.0), so minor type drift is possible.

## Plan implications

- Import pipeline: POST /api/imports is a route handler, not a server action, with an 8 MB cap. Detect the type from magic bytes: 'PK' = xlsx, D0 CF 11 E0 = legacy xls/OLE, anything else is text. Spreadsheets go through XLSX.read(buf, {type:'buffer', cellDates:true, dense:true}) then sheet_to_json(ws, {header:1, raw:true, defval:'', blankrows:false}), with a sheet picker when there are several sheets. Text goes through a UTF-8-fatal decode with a windows-1252 fallback, then Papa.parse(text, {skipEmptyLines:'greedy'}) with auto delimiter. Pasted rows come from a textarea (onPaste, text/plain), and the delimiter is forced to '\t' when the text contains tabs. Store rows in an ImportSession/ImportRow staging table, then show the mapping UI and preview, then commit in chunked transactions (a worker job for large files), and produce the result summary.
- CSV export: Papa.unparse(rows, {escapeFormulae:true, newline:'\r\n'}), prefixed with '﻿', sent as Content-Type 'text/csv; charset=utf-8' with Content-Disposition attachment. Offer comma or semicolon (per-user preference) and optionally an .xlsx export via SheetJS. The missing-emails export carries a stable company ID column. The re-import matches on that ID first and strips a leading ' added by formula escaping.
- Country module in lib/geo/: normalizeCountry(input) works in this order. Trim and remove diacritics; handle 2-letter codes (special cases UK→GB, EL→GR); handle 3-letter codes via alpha3ToAlpha2; try getSimpleAlpha2Code across [en, de, nb, nn, no, sv, da, nl, fr, es, it, pt, pl]; then an app alias map (England/Scotland/Wales→GB, Holland→NL, etc.). If nothing matches, flag the row as 'unknown country' in the import preview. Use Intl.DisplayNames for showing names in the UI, so the client bundle has no country library.
- Country→default zone: a static map committed to the repo (lib/geo/default-zones.ts), generated once from Node's Intl.Locale('und-XX').getTimeZones() and using modern IANA names (Asia/Kolkata, Europe/Kyiv). It has explicit main zones for multi-zone countries: US America/New_York, CA America/Toronto, AU Australia/Sydney, BR America/Sao_Paulo, RU Europe/Moscow, MX America/Mexico_City, ES Europe/Madrid, PT Europe/Lisbon, DE Europe/Berlin, NZ Pacific/Auckland, ID Asia/Jakarta, KZ Asia/Almaty, CN Asia/Shanghai, AR America/Argentina/Buenos_Aires, CL America/Santiago. Each company's zone stays editable. Validate zones with new Intl.DateTimeFormat. Do not use countries-and-timezones.
- All times are stored as UTC instants (Prisma DateTime). One lib/time.ts module wraps `import { Temporal } from 'temporal-polyfill'` and exports nextSendSlot(now, tz, window), addBusinessDays, followUpDueAt and similar. It uses PlainDate.dayOfWeek (1 = Mon) and toZonedDateTime({timeZone, plainTime}) with the default 'compatible' disambiguation. Unit tests cover the Europe DST changes (2026-03-29 and 2026-10-25, Europe/Berlin), the US changes (2026-03-08 and 2026-11-01), Friday 16:59 → Monday 09:00, and PKT viewer display. The UI formats times with Intl.DateTimeFormat in the viewer's zone, not with Temporal.
- Worker build: `npm run build` runs `next build`, then `esbuild worker/index.ts --bundle --platform=node --format=esm --target=node24 --packages=external --outfile=dist/worker.mjs`. PM2 or start.bat runs `node dist/worker.mjs`. Development uses `tsx watch worker/index.ts`. Milestone 1 includes a spike: bundle the worker, run one Prisma query through the better-sqlite3 adapter, and if bundling fails switch production to `node --import tsx worker/index.ts`. Prefer string-literal unions and `as const` objects over TS enums everywhere, to keep every runtime option open.
- Tooling pins: typescript ~6.0.3, eslint-config-next 16.3.6 (flat config), vitest 5.0.1 + vite 8.x (resolve.tsconfigPaths: true, environment 'node' for logic tests), @playwright/test 1.63.0 with chromium only. `npm run check` runs `tsc --noEmit`, then eslint, then vitest run.
- Contacts screen: server-side pagination (50/100/200 per page) driven by URL search params (list, status, tag, country, niche, priority, emailed, hasEmail, firstContactedBy, q, sort, page). Prisma queries use SQLite indexes on status, country, niche, priority, lastEmailedAt and nameNormalized. Status tab counts come from one groupBy. TanStack Table v9 runs in manual mode (manualPagination, manualSorting, manualFiltering, rowCount) with rowSelectionFeature and getRowId = company id. Selected IDs are kept in client state across pages, with a 'N selected' bar and 'clear'. Bulk server actions receive an explicit ID array, matching the spec's 'selected rows only' rule. No virtualization on this screen.
- Validation: zod 4 schemas in lib/validation shared by client and server. Every server action runs requireUser() or requireOwner() first, then schema.safeParse, and returns z.flattenError(err).fieldErrors to useActionState. The same schemas validate route-handler JSON and worker job payloads.
- Email hygiene in lib/email/address.ts. normalize(): trim; strip 'mailto:', surrounding '<>' and trailing punctuation; parse 'Name <addr>'; convert the domain with url.domainToASCII. Dedupe key = lowercased full address. Validate with z.email(). isRoleAddress(): a curated in-app list of local-parts (info, contact, kontakt, hello, hallo, hei, post, postmottak, firmapost, mail, email, office, buero, sales, salg, verkauf, vertrieb, support, service, kundeservice, kundenservice, team, admin, booking, bestilling, order, orders, bestellung, anfrage, enquiries, inquiries, studio, shop, print, marketing, press, presse, jobs), OR'd with Mailgun's is_role_address after verification. Role addresses are created as a person named 'General inbox'.
- Login throttling with no Redis and no library: a LoginAttempt table (id, emailNormalized, ip, success, createdAt). Rule: at most 5 failed attempts per account per 15 minutes, then a 15-minute lock, plus at most 30 failures per IP per 15 minutes. The client IP is CF-Connecting-IP when present, otherwise x-forwarded-for, otherwise 'lan'. Return the same generic error and similar timing for all failures, and prune rows older than 7 days in a worker job. Record lockouts in the audit log.
- Secrets in lib/crypto/secrets.ts. APP_ENCRYPTION_KEY in .env is base64 of 32 random bytes; the first-run script generates it with node -e "console.log(require('crypto').randomBytes(32).toString('base64'))". Stored format is 'v1:' + base64(iv12) + ':' + base64(tag16) + ':' + base64(ciphertext). AAD is the setting name, so ciphertext can't be swapped between fields. authTagLength:16 is used on both sides. The key version prefix allows rotation. The UI only shows 'saved • last 4 characters'. The README tells the owner to back up .env separately from the database backups.
- Live updates by polling, not SSE. The bell calls GET /api/notifications/summary every 20 s (a cheap indexed count plus the latest id), pauses while document.hidden, and refreshes on focus. Progress screens (sending, import, AI drafts, verification) poll a job-status endpoint every 2–3 s only while a job is running. This works the same over the LAN and through Cloudflare Tunnel, with no buffering, timeout or 6-connection issues. Desktop notifications are offered only when window.isSecureContext is true (the https tunnel hostname).
- The session cookie is httpOnly with SameSite=Lax. Secure is set only when the request came in over https (x-forwarded-proto === 'https' via cloudflared), so login keeps working at http://<pc-ip>:<port>. The copy-to-clipboard button falls back to execCommand('copy') or a select-all text box when navigator.clipboard is missing.
- Testing: Vitest runs unit tests (template rendering, column matching, 30-day rule, windows and caps, warm-up, health pause, webhook HMAC, reply and auto-reply detection) and integration tests against a temporary SQLite file per test file (copied from a migrated template DB). The E2E test is a Vitest script (tests/e2e/dry-run.test.ts). It builds, starts `next start` on a test port with a test DATABASE_URL and SEND_MODE=dry-run, starts the worker, then over fetch with a cookie jar it logs in, uploads a CSV, approves mocked AI lines, creates a campaign with 2 follow-ups, advances a fake clock, posts HMAC-signed bounce, unsubscribe and inbound-reply webhooks, and checks the DB and dashboard API. A small Playwright smoke suite (chromium) opens the key screens so each milestone's 'screens really work' check is automated.
- Instagram handles are shown with our own small inline SVG icon, because lucide 1.x has no brand icons.
